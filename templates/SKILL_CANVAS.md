# Skill Canvas

先从真实对话和案例自动整理，再只补会改变设计的空缺。括号内是提示，完成时删除。

## Name

`your-skill-name`（简短、具体、使用小写字母和连字符）

## Purpose

这个 Skill 反复解决什么问题？

## User

谁在什么场景使用？

## Required Input

缺少哪些信息就无法可靠完成？

## Optional Input

哪些信息能改善结果？缺少时如何降级？

## Analyze

开始前要观察哪些信号？

## Decisions

哪些条件会改变做法？尽量写成“如果……则……”。

## Workflow

用户真实的步骤、分支和返工循环是什么？

## Knowledge

哪些个人判断、失败经验或标准值得按需保存？

## Router

是否存在两条以上真正不同的流程？没有就写“不需要”。

## Hard Constraints

绝对不能违反什么？

## Preferences

优先遵守、但允许按场景权衡什么？

## Output

最终交付什么？包含多少项、哪些字段、什么格式？

## Quality Check

怎样判断结果完整、正确、可执行？

## Repair

检查失败后修什么，并回到哪一步复查？

## Tools

是否真的需要最新信息、计算、文件处理或外部系统？

## Tests

用哪些正常与异常输入证明它能工作？
