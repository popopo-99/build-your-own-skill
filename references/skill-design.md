# Skill 设计：从想法到清晰边界

## Prompt、Workflow 与 Skill

- **Prompt** 通常解决一次任务：告诉 AI 这次做什么。
- **工作流（Workflow）** 解决一类任务：定义稳定的步骤和分支。
- **Skill** 是可重复执行的专业能力：包含触发条件、工作流、判断规则、约束、输出和检查方式。

一个 Skill 不以字数或文件数量取胜。它的价值来自用户解决问题的方法能否被稳定复现。

## 判断想法是否值得做成 Skill

优先选择同时具备以下特征的想法：

1. 会重复发生，而不是一次性请求；
2. 包含判断、取舍或专业经验，而不只是固定文本；
3. 输入和输出可以描述；
4. 结果能够检查；
5. 把方法交给 AI 后，确实能节省时间或提高一致性。

如果只是替换固定词语，一段模板可能已经足够。如果需要稳定的文件转换或计算，可能需要脚本；但先确认文字工作流无法可靠完成。

## Skill Statement

先替用户起草，再让用户修正：

> 当用户需要 ______ 时，这个 Skill 会通过 ______ 的方法，帮助用户得到 ______。

好的 Statement 同时说明触发场景、核心方法和可观察产物。

较弱：

> 帮助用户做更好的品牌设计。

较强：

> 当用户需要建立品牌视觉方向时，这个 Skill 会通过品牌阶段、受众、定位和视觉机会分析，帮助用户得到三套差异明确且能由设计团队执行的方向。

## 定义边界

### Purpose

只描述第一版要解决的核心问题。避免把相邻能力全部纳入。

### User

谁会直接使用它？使用者和最终受益者可能不同。例如，使用者是摄影师，最终客户是餐厅品牌。

### Inputs

区分：

- **Required Input**：缺少就无法可靠工作；
- **Optional Input**：能提高质量，但缺少时可以使用假设或降级方案。

### Outputs

定义实际交付物、数量、结构和必要字段。不要只写“提供专业建议”。

### Constraints

区分不可违反的 Hard Constraints 与可根据上下文调整的 Preferences。冲突时先遵守 Hard Constraints，并说明无法同时满足的要求。

### Out of Scope

明确第一版不处理什么。边界能减少错误触发，也能防止“万能 Skill”不断膨胀。

## 避免万能 Skill

范围过宽时，可沿一个或多个维度缩小：

| 维度 | 宽泛 | 更适合 V0.1 |
| --- | --- | --- |
| 用户 | 所有人 | 独立餐厅品牌团队 |
| 场景 | 所有摄影 | 菜单与宣传照拍摄规划 |
| 输入 | 任意材料 | 餐厅 Brief、菜品表和场地照片 |
| 输出 | 完整营销 | 可执行拍摄顺序与镜头清单 |
| 决策 | 全部创意 | 视觉方向差异化判断 |

如果多个任务共享相同输入但采用真正不同的流程，未来可以增加 Router；第一版不必提前合并。

## 何时不创建复杂 Skill

- 问题只会发生一次；
- 用户还无法描述任何真实案例；
- 结果完全依赖当前人的主观临场决定，暂时无法解释判断；
- 普通 Prompt 或清单已经稳定解决问题；
- 为了显得专业才想加入 Router、API、数据库或脚本。

此时应交付较小的 Prompt、模板或 Discovery 记录，并说明以后在什么证据出现时再升级。
