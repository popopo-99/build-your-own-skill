# Quick Discovery：从经验中找到真正的方法

Discovery（发现）不是闲聊，也不是收集个人履历。它的目标是找到一个值得被结构化的真实方法：用户反复解决什么问题、如何判断、何时改变做法，以及怎样知道结果合格。

这是默认的 Quick Discovery（快速发现）：优先利用已有上下文，每轮只问 1–3 个高价值问题，信息足够就停。用户明确要求“深挖、多问问我、采访我、帮我想清楚”时，转到 [Deep Discovery](deep-discovery.md)。若少量 Quick 轮次后仍有会根本改变 Scope / Workflow 的重大缺口，先说明缺口并询问是否愿意深挖；用户可以拒绝，不因此自动进入长访谈。用户想快速推进时，说明尚未验证的假设或缩小范围，保持 READ / DESIGN 和 Write Gate。

## 1. 先找重复问题

从具体工作片段开始，不要求用户先定义“我要做什么 Skill”。优先寻找：

- 经常重复完成、但每次都需要判断的任务；
- 别人会主动来请教用户的问题；
- 用户觉得“这件事其实有方法”的场景；
- 新手容易犯错，而用户能快速发现的场景；
- 有明确输入、过程和结果的工作。

弱信号是“我懂设计”“我会运营”。强信号是“我每周都把餐厅新品 Brief 转成一套拍摄清单，并提前排除反光、融化和出餐节奏问题”。

## 2. 从真实案例提取隐性知识

请用户回忆最近一次真实任务，沿着事实追问：

1. 拿到任务时第一眼看了什么？
2. 先做了什么判断？为什么？
3. 哪些条件会让做法改变？
4. 哪一步不能跳过？
5. 什么方案会被直接否掉？
6. 最后如何判断合格或优秀？

不要问“你的方法论是什么”后等待完整答案。用户的隐性知识通常藏在案例、比较、例外、习惯和失败里。

## 3. 五类高价值信息

### 判断线索

用户注意哪些变量，以及它们为什么重要。

示例：餐厅摄影师先看出餐速度，因为它决定拍摄顺序和需要准备的替身食物。

### 决策规则

出现某种条件时采取什么做法。

示例：如果菜品表面快速失去光泽，先拍近景主视觉，再补俯拍菜单图。

### 失败模式

什么常常失败、失败信号是什么、用户怎样补救。

### 质量标准

“合格”和“优秀”分别意味着什么，最好能由他人观察或检查。

### 边界与例外

哪些任务不属于这套方法，哪些情况必须切换流程或交给人工判断。

## 4. 高价值问题库

每轮选择 1–3 个最能减少不确定性的问题，不要按顺序全问：

- 你最近一次完成这件事时，实际步骤是什么？
- 别人通常在哪个环节最需要你的帮助？
- 你拿到材料后最先看哪三个信号？
- 哪些错误你一眼能发现，但新手通常发现不了？
- 什么情况会让你改变原来的做法？
- 什么方案即使看起来不错，你也会直接否掉？为什么？
- 哪些检查每次都不能省？
- 结果达到什么程度算合格？什么让它变成优秀？
- 能否给一个成功案例和一个失败案例？两者差在哪里？
- 这套方法在哪些场景不适用？

## 5. 避免机械问卷

- 先复述已经理解的部分，再问最大缺口。
- 用户已经在案例中给出 User、Input 或 Workflow 时，直接填入 Canvas。
- 能合理推断且风险低的内容，用明确假设继续，不重复询问。
- 同一轮不要同时追问 Purpose、User、Input、Output 等十几个字段。
- 问题使用用户的职业语言，不让用户解释 YAML、Router、Output Contract。

对话示例：

> 你真正擅长的似乎不是“拍美食”，而是把出餐限制转成可靠的拍摄顺序。为了确认第一版边界，我还想知道：你通常根据哪些信号决定先拍哪道菜？如果现场延误，你怎么重排？

## 6. 缩小 Scope

用四项检查候选问题：

- **重复性**：是否会再次发生？
- **独特判断**：用户的方法是否超出百科常识？
- **可执行性**：是否能写成步骤、分支或检查？
- **可验证性**：能否判断结果是否满足要求？

若题目太宽，按用户类型、使用场景、输入、产物或关键决策缩小。

例如：

- “摄影 Skill” → “餐厅菜单摄影方案规划”；
- “小红书 Skill” → “基于品牌素材生成可验证的选题池”；
- “设计助手” → “从品牌 Brief 生成三套差异明确的视觉方向”。

## 7. 何时停止 Discovery

满足以下大部分条件即可推进，不必追求信息完美：

- 能说清一个具体、重复的问题；
- 至少有一个真实案例；
- 知道主要输入和期望结果；
- 能描述关键步骤或决策；
- 已发现一条用户特有的判断规则；
- 有基本的失败或质量判断；
- 边界足以形成 V0.1。

然后主动给出候选 Skill Statement 和初步 Skill Canvas，请用户修正关键误解，而不是继续盘问。
