# 从真实工作经验到 Skill：活动视觉方向

*Experience → Skill*

## 起点

用户是一名视觉设计师，经常处理活动、青年文化与音乐节项目中较模糊的 Brief。起点不是现成 Prompt 或 SOP，而是一套在真实工作中形成、尚未显式写下来的判断方式。

用户手里已有的是：如何判断活动真正要解决的问题、目标受众、相关青年文化与文化现象、参与机制、视觉世界观，以及项目周期、宣传周期、制作和运营约束。用户也明确关心三套提案是否真的结构不同，而不只是换配色。

## 原始问题

经过整理，问题可以概括为：如何把设计师面对模糊活动 Brief 时形成视觉方向、判断文化依据、区分三套方案并检查落地条件的方法，变成一个可以重复执行和测试的 Skill。

这里没有把对话伪装成逐字记录。重要的是保留真实起点：用户有工作经验，但还没有现成的 Skill 结构。

## Build Your Own Skill 识别到了什么

这个任务从 **Discovery → Design → Build** 展开：

1. **Discovery** 从实际工作问题中寻找重复出现的判断，而不是立刻生成文件。
2. **Design** 把经验整理为 Scope、Workflow、约束、输出、检查与测试。
3. **Build** 在范围收敛后，生成真实的 [`event-visual-directions`](final/SKILL.md) Skill 与[行为测试](final/tests/cases.md)。

最终目标不是“AI 帮设计师想三个方向”，而是“把设计师判断三个方向是否真的不同、是否有文化依据、是否能落地的方法做成 Skill”。

## 被提取出的隐性知识

隐性知识（Tacit Knowledge）在整理时保留了来源差异：

### USER-DERIVED

- 先判断活动真正需要解决的问题与目标受众，而不是直接找风格。
- 把青年文化、文化现象、参与机制和视觉世界观放在同一判断过程里。
- 同时考虑项目周期、宣传周期、制作与运营约束。
- 三套方案必须在结构上真的不同，不能只是更换颜色或表面风格。

### INFERRED

- 从真实案例可进一步归纳：文化参考需要区分表面符号与促使人参与的内在机制。
- “观察到的文化信号”“对信号的解释”和“由此产生的创意跳跃”需要分开，避免把假设写成事实。
- 三套方向建立后，空间行为与人与活动的关系可作为后续深化，而不是先用这些概念制造表面差异。

这些内容是对真实案例的归纳，不被表述为用户逐字提出的原规则。

### PROPOSED

- 用六个比较轴把“结构不同”变成可检查的规则。
- 用 Feasibility Gate 把周期、运营、制作与认知成本变成统一筛选步骤。
- 用明确的 Output、Check / Repair 和 Behavioral Tests 让方法可复用、可验证。

这些是 Build Your Own Skill 为结构化和测试提供的补充，不冒充设计师原有的术语体系。

## Scope 如何收敛

V0.1 没有被做成“万能视觉设计 Skill”。它被限定在青年文化活动、音乐节、夜生活、快闪和类似现场体验的早期概念与视觉方向工作。

它不负责最终 Logo、完成稿、施工图、精确预算或完整 Campaign，也不声称已经验证了纯企业品牌和长期识别项目。这样的边界让输入、关键决策和输出都能被描述与测试。

## Workflow 如何形成

最终核心工作流是：

1. 提取已知 Brief，并区分事实、客户说法、受众假设和矛盾。
2. 诊断表面需求背后的真实体验问题。
3. 验证当下文化信号，区分观察、解释和创意跳跃。
4. 寻找文化领域，拆开表面符号与参与机制。
5. 将机制转译为原创的活动世界、参与理由和视觉语法。
6. 建立三套方向骨架，并进行六轴差异检查。
7. 通过 Feasibility Gate 检查真实落地条件。
8. 用合适的目标人群验证，并在修改时锁定未请求变化的部分。

这条流程把“我一般会怎么判断”变成了可执行步骤，同时保留了不确定性和需要验证的假设。

## 为什么三套方案不能只是换颜色

如果三套方案共享同一种情绪、世界规则和参与方式，只换色板或参考图，它们仍然是同一个方向。最终 Skill 要求任意两套方向在六个轴上都有实质差异：

- **Core emotion**：希望参与者感受到什么。
- **Worldview**：活动世界的前提、规则与意义。
- **Interaction mechanism**：参与者实际做什么，如何发现或获得反馈。
- **Composition language**：层级、尺度、密度、节奏、框取与图文关系。
- **Material language**：表面、触感、光线反应和制作气质。
- **Color system**：不只换色相，还改变层级、对比、饱和度、明度、空间用法及其与材质的关系。

这个矩阵让“真的不同”成为可以逐项检查的质量标准。

## 为什么加入 Feasibility Gate

活动方向能被画出来，不等于能被理解和执行。Feasibility Gate 检查：受众理解世界观需要多久、宣传内容需要多长铺垫、是否依赖持续教育、是否需要 NPC 或专业协作者、现场运营有多少移动环节、制作难度与失败点，以及核心承诺在简化后能否保留。

对于短周期项目，Skill 会偏向一眼可懂、无需学习大量规则也能参与的方案。如果一个强概念超出当前周期，它不会被假装成“可落地”，而是提取最小可测试吸引力，并把完整版标记为当前不适用。

## 最终架构

- [`final/SKILL.md`](final/SKILL.md)：保存 Scope、工作 Brief、核心 Workflow、六轴差异、Feasibility Gate、输出契约、约束与 Check / Repair。
- [`final/tests/cases.md`](final/tests/cases.md)：保存针对真实风险的行为测试。

这个案例只保留实际生成结果，没有为讲解额外伪造 Router、scripts 或 references。

## 测试

最终测试覆盖了八类真实风险：标准青年音乐节 Brief、最少输入、文化借鉴变成表面复制、好创意但宣传周期不足、用风格变化伪装结构重复、无法验证的当下文化判断、只修改一个已有方向时发生漂移，以及超出 V0.1 边界的纯企业品牌 Brief。

这些测试验证的不只是输出是否“好看”，还包括是否少问关键问题、是否标记证据不足、是否守住 Scope、是否按六轴区分，以及是否通过现实约束筛选。

## 这个案例教会了什么

- 没有 Prompt 也可以开始；真实案例中的判断比格式更重要。
- Skill 的核心不是替用户想创意，而是稳定复用用户判断创意的方法。
- 模糊的“方向要不同”需要变成可检查的比较轴。
- 创意质量与落地可行性必须同时进入流程。
- V0.1 的边界越明确，行为测试越能指出真正的问题。
