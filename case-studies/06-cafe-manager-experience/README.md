# 咖啡店店长：把备货排班经验变成异常与风险判断 Skill

> “我不会写代码，但每天都要凭经验决定备多少货、什么时候调人，这也能做成 Skill 吗？”

这是基于真实 Runtime 对话整理的教学案例。门店场景、品类和细节经过匿名化、改写或复合设计，没有使用真实门店、公司、客户或商业数据；案例演示经验提取，不是经营效果证明。

## 1. 用户一开始只有什么

用户每天要判断牛奶、燕麦奶、冷萃和易损甜品的准备量，也要在高峰时决定是否增援。现有做法看起来像“看看昨天卖了多少再凭感觉调整”，但用户知道昨日销量异常时不能直接照抄，也知道每种品类判断错后的后果不同。

这是一套真实的工作经验，却没有公式、Prompt 或技术文档。

## 2. Skill 没有立刻做什么

- 没有要求用户写代码、提供数据库或建立预测系统。
- 没有把昨天销量、平均值直接当成今天的备货答案。
- 没有把所有品类套进同一个安全库存比例。
- 没有看到门店忙就直接建议加人，也没有自动修改排班。

## 3. 它问了什么

1. **昨天销量异常时，你先改数量，还是先判断发生了什么？** 这会暴露异常归因是整个流程的上游步骤。
2. **不同品类如果备少或备多，补救方式和损失有什么不同？** 这个问题把模糊的“保险一点”拆成可补货时间、缺货影响和损耗成本。
3. **高峰时你依据什么判断需要增援？** “很忙”不够具体，需要观察订单进入速度是否持续超过处理速度。
4. **决定调人后，你先找什么？什么时候让人回原岗位？** 这能找出点单、出杯、打包或现场服务的真正瓶颈，并定义恢复条件。

## 4. 从案例中发现了什么

- 销量异常后，第一步不是改备货数量，而是找异常原因并判断今天是否仍存在。
- 判断要拆到品类、时段和渠道，不能只看全天总量。
- 备多少不仅取决于可能卖多少，也取决于缺货后能否补、多久能补、备多后的损失。
- 牛奶、燕麦奶、冷萃和易损甜品具有不同的容错空间。
- 高峰增援需要持续积压信号和具体瓶颈，不是看到队伍就永久改班。
- 短时增援结束后应恢复原工作，不因一次峰值推翻整天安排。

## 5. 从经验到规则

| 原始经验 | 提取出的判断 | 可以写进 Skill 的规则 |
| --- | --- | --- |
| “昨天卖得特别多也不一定多备” | 异常可能不可重复 | 先记录异常原因，再判断原因今天是否仍存在 |
| “有的少了能补，有的来不及” | 补救能力决定风险 | 对每个品类检查补货可行性、补货时间和缺货影响 |
| “甜品多了会浪费” | 过量成本因品类而异 | 将损耗和保质窗口纳入备货取舍，不统一加百分比 |
| “忙了也不一定要加人” | 先判断积压是否持续 | 只有订单进入持续快于处理速度时才进入瓶颈诊断 |
| “调人要调到堵点” | 人多不等于流量改善 | 识别点单、出杯、打包或现场服务瓶颈，并定义退出条件 |

## 6. 最终找到的 Skill

**Skill Statement**：当咖啡店店长需要安排当日备货和高峰增援时，通过异常归因、分品类风险、补救能力和岗位瓶颈判断，给出可解释、可调整的准备建议。

- **适用边界**：日常运营判断辅助；不自动下单、不修改排班，也不声称替代食品安全、财务或劳动规则。
- **核心 Workflow**：检查历史异常 → 判断原因是否延续 → 分品类 / 时段 / 渠道 → 权衡缺货与损耗 → 观察持续积压 → 定位岗位瓶颈 → 设置恢复条件。
- **Hard Constraints**：不能只按昨日销量或平均值；不能对不同品类使用同一容错；不能在未定位瓶颈时直接调人。
- **Output**：已知情况、异常解释、分项建议、风险与补救方式、需要观察的信号及未确定事项。
- **Check / Repair**：检查异常是否被解释、建议是否考虑补救和损耗、增援是否对应瓶颈；信息不足时说明需要观察什么，不编造销量或人数。

V0.1 可以保持为说明型 Skill，不需要 API、数据库或自动化排班系统。

## 7. 为什么这不是普通 Prompt

普通 Prompt 可能问“明天该备多少牛奶”。这里保存的是处理一类问题的方法：为什么异常不能直接外推、什么情况改变品类策略、判断错后怎样补救、什么时候才需要增援，以及如何检查建议是否遗漏风险。它让经验能面对不同日期，而不是给一次孤立答案。

## 8. 你可以照着怎么开始

```text
$build-your-own-skill

我每天都要决定备货和高峰期怎么调人。
我不会写代码，也没有整理过方法，但我知道很多情况不能只看昨天销量。
请从最近一次销量异常或门店拥堵的例子开始，帮我找出判断规则，
先不要创建或修改文件。
```

## 9. 这个案例真正值得学什么

- Skill 不要求复杂公式；异常判断、取舍和补救逻辑同样是专业知识。
- “判断错了以后能否补救”常比追求一个精确预测数字更有用。
- 非技术职业也可以先用自然语言提取方法，从最小 V0.1 开始。
