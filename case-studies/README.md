# Real Case Studies

这些案例不是为了展示一份“漂亮的 `SKILL.md`”，而是展示一个 Skill 如何被发现、拆解、构建和诊断。

`examples/` 展示“一个 Skill 最后长什么样”；`case-studies/` 展示“人们如何从不同起点一步步找到并整理自己的方法”。

## 案例说明

Case 01–03 保留仓库早期真实实机测试的不同起点与产物。Case 04–06 是教学化的实机演示：对话流程来自真实的 Build Your Own Skill Runtime 使用，职业场景、数据和细节经过匿名化、改写或复合设计，用于保护隐私并让教学结构更清楚。

这些内容不是未经处理的客户或用户资料，也不证明其中的职业方法普遍有效。案例重点是展示如何从具体经历提取判断、流程、约束和检查。

| 你现在手里有什么 | 案例 | 路径 |
| --- | --- | --- |
| 只有工作经验，不知道怎么整理 | 从专业经验到 Skill | [Experience → Skill](01-experience-to-skill/) |
| 已经有一条越来越长的 Prompt | 从长 Prompt 到 Skill | [Prompt → Skill](02-prompt-to-skill/) |
| 已经有 Skill，但不好用 | Review / Repair | [Review → Repair](03-review-and-repair/) |

### Case 01

没有现成 Prompt，从视觉设计师处理模糊活动 Brief 的真实工作经验开始，逐步提取判断、约束、流程与测试。

### Case 02

已有一条长期使用、效果不错但难以维护的成熟 Prompt，将其中隐含的结构拆成明确 Workflow、永久视觉 DNA、检查与修复机制。

### Case 03

已有能运行的 Skill，不重新构建；先定位不稳定行为的根因，再提出最小修复（Minimum Change）与回归测试。

不要只看最终文件。真正值得学习的是：为什么问这些问题、为什么做这些判断、为什么有些东西没有被加入 Skill。

## 不同行业，可以怎么做自己的 Skill？

| 职业 | 从哪里开始 | 找到了什么 |
| --- | --- | --- |
| 视觉设计师 | “我想做 Skill，但不知道什么值得做” | [从模糊活动 Brief 找到创意方向判断方法](04-visual-designer-discovery/) |
| AIGC 短剧导演 | “我会拆镜头，但说不清自己的方法” | [把戏剧判断与制作拆解变成规则](05-aigc-director-experience/) |
| 咖啡店店长 | “我每天都凭经验备货排班” | [把异常、补救成本和岗位瓶颈变成流程](06-cafe-manager-experience/) |

> 值得做成 Skill 的，不一定是复杂知识。只要你长期重复解决一个问题，并且已经形成自己的判断、取舍和例外处理方式，就可能值得整理。
