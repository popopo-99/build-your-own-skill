# 视觉设计师：从“不知道做什么”到活动创意方向 Skill

> “我是做视觉设计的，也想做一个自己的 Skill，但我不知道什么最值得做。”

这是基于真实 Runtime 对话整理的教学案例。职业场景与细节经过匿名化、改写或复合设计；它展示方法提取过程，不是未经处理的用户资料，也不是活动策划效果报告。

## 1. 用户一开始只有什么

用户只有一次熟悉却难整理的工作情境：线下活动客户说要“年轻、潮流、适合拍照、不像普通市集”，又给了大量风格混杂的参考。用户知道不能直接拼贴风格，却还没有说出自己真正反复在做的判断，也不知道该把哪一部分做成 Skill。

## 2. Skill 没有立刻做什么

- 没有马上创建 `SKILL.md`，也没有要求用户先取名。
- 没有让用户填写 YAML、Canvas 或技术表格。
- 没有把“年轻、潮流”直接翻译成一套 AI 熟悉的视觉风格。
- 没有把任务扩张为完整活动策划、最终视觉稿或执行手册。

## 3. 它问了什么

教学整理保留了三类关键问题：

1. **拿到这种 Brief 时，你第一步判断什么？** 这不是问设计偏好，而是寻找用户比新手更早做出的上游判断。
2. **这些形容词最终希望观众发生什么行为？** 这个问题把抽象风格词转为可观察的参与动机，并检验三套方向是否只是在换皮。
3. **哪个“好看”的概念最后没成立？删掉复杂执行后还剩什么？** 反例会暴露成本、世界观、NPC、剧情和运营依赖，也能找到否决规则。

问题没有一次问完所有字段。每一轮都用上一轮的真实案例决定下一步，信息足够形成第一版时就停止 Discovery。

## 4. 从案例中发现了什么

- 用户真正擅长的不是“找潮流风格”，而是先判断活动要促成什么参与行为。
- 三个创意方向的差异应来自参与动机、观众角色和互动关系，而不只是颜色、字体或装饰语言。
- 强世界观可能有吸引力，也可能带来解释、人员、剧情和运营成本。
- 如果删掉复杂执行后只剩一层视觉包装，原概念需要重新考虑。
- “适合拍照”不是一个完整方向；需要继续说明人为什么愿意进入、参与和分享。

## 5. 从经验到规则

| 原始经验 | 提取出的判断 | 可以写进 Skill 的规则 |
| --- | --- | --- |
| 客户常给一堆混杂参考 | 参考图不是需求本身 | 先提取活动目标、受众与期望行为，再讨论风格 |
| 三套方案容易只换皮 | 真差异来自体验结构 | 候选必须在参与动机、观众角色或互动关系上形成实质差异 |
| 有些概念很好看但太重 | 创意要承担真实执行成本 | 检查世界观解释、NPC、剧情、制作和运营依赖 |
| 复杂环节一删就只剩包装 | 核心机制并未成立 | 做“最小化检查”：删去复杂执行后，仍需保留独立的参与理由 |

## 6. 最终找到的 Skill

**Skill Statement**：当视觉设计师面对形容词模糊、参考混杂的线下活动 Brief 时，通过目标诊断、行为转译、结构差异和可行性检查，形成可继续视觉实验的活动创意方向。

- **适用边界**：早期活动创意方向；不负责最终 Logo、全案策划、施工图或精确预算。
- **核心 Workflow**：整理 Brief → 判断真实活动目标 → 把形容词转成观众行为 → 建立结构不同的候选 → 检查执行负担 → 收束可继续发展的方向。
- **Hard Constraints**：不能把三套视觉皮肤当三套创意；不能隐瞒高成本依赖；不能把参考图当成已经验证的文化事实。
- **Output**：活动问题、目标行为、候选方向骨架、结构差异、执行风险与下一步视觉实验。
- **Check / Repair**：检查候选是否只换风格、核心是否依赖复杂解释；失败时回到参与机制或缩小概念，而不是继续加装饰。

V0.1 不需要 Router、脚本或生成图片工具。先把判断方法写清楚即可。

## 7. 为什么这不是普通 Prompt

普通 Prompt 可以请求“一次生成三套年轻潮流的活动方向”。这里保存的是可复用的判断：为什么先看活动目标、什么情况使三个方向仍然相同、哪些执行依赖会否掉概念，以及怎样发现“复杂内容删完只剩包装”。它不仅规定产出，还规定决策、边界和修复。

## 8. 你可以照着怎么开始

```text
$build-your-own-skill

我经常处理信息很模糊、参考又很杂的视觉 Brief。
我应该已经有一套判断方向的方法，但不知道什么最值得做成 Skill。
请先通过我最近做过的一次项目帮我找出这套方法，
先不要创建或修改文件。
```

## 9. 这个案例真正值得学什么

- 不知道该做什么 Skill 时，从一件最近反复判断的真实工作开始。
- 抽象形容词背后，常藏着用户行为、取舍与否决条件。
- 第一版只需要保住核心判断，不必把整个职业做成一个 Skill。
